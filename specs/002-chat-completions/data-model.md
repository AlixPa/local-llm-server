# Data Model: Chat Completions End to End

Follows `.claude/CLAUDE.md` DB conventions: singular PascalCase model → plural snake_case table,
integer surrogate PK plus unique `external_id`, `db.types.UtcDateTime` for datetimes, SQLite
naming convention already on `Base`. Models live in `packages/db/src/db/models/chat_completions.py`.
No soft delete and no lifecycle columns beyond those below (nothing is edited or deleted).

## ChatCompletionRecord → `chat_completion_records` (metadata, exposed to Analytics)

| Column | Type | Notes |
|---|---|---|
| `id` | int PK | internal |
| `external_id` | str, unique | OpenAI-style `chatcmpl-<random>`; same id as the response |
| `created_at` | UtcDateTime | request start; API exposes it as integer unix `created` |
| `model` | str | model id the client sent (equals a served model on success; the unknown name on `model_not_found`) |
| `status` | `StrEnum` `ChatCompletionStatus` | `succeeded`, `failed`, `cancelled` |
| `stream` | bool | |
| `n` | int | choices requested |
| `prompt_tokens` | int, null | null when unknown (early failure) |
| `completion_tokens` | int, null | |
| `duration_ms` | int | wall-clock, request start → end |
| `time_to_first_token_ms` | int, null | streaming only |
| `generation_duration_ms` | int, null | Ollama `eval_duration` (summed for `n > 1`) |
| `load_duration_ms` | int, null | Ollama `load_duration`; kept for performance analysis of the Ollama server (cold loads), unrecoverable if not captured |
| `finish_reason` | str, null | first choice's reason |
| `error_type` | str, null | OpenAI error `type` when failed |
| `error_code` | str, null | OpenAI error `code` when failed |

Index: `(created_at DESC, id DESC)` for cursor pagination. `total_tokens` is derived, not stored.

## ChatCompletionContent → `chat_completion_contents` (never exposed to Analytics)

| Column | Type | Notes |
|---|---|---|
| `id` | int PK | |
| `record_id` | int FK → `chat_completion_records.id`, unique, `ON DELETE CASCADE` | 1:1 |
| `request` | JSON | messages and all other request parameters as received |
| `response` | JSON, null | choices (content, tool calls) as returned; null on failure; partial text on cancel if any |
| `error_message` | str, null | full error message |

## Model → `models` (served models; source of `GET /v1/models` and request validation)

| Column | Type | Notes |
|---|---|---|
| `id` | int PK | internal |
| `external_id` | str, unique | the model id = Ollama tag, e.g. `qwen3.5:9b` |
| `created_at` | UtcDateTime | exposed as integer unix `created` |
| `owned_by` | str | e.g. `qwen` |

Seeded with one row (`qwen3.5:9b`) by the migration; no write path in the API.

## State

A record is inserted once, in its final state. `succeeded` (completed normally), `failed`
(returned or streamed an error), `cancelled` (client disconnected during generation, streaming or not). No transitions.

## DB package operations (`packages/db/src/db/repositories/chat_completions.py`)

Only what this feature needs; the API calls these and runs no queries itself.

- `create_chat_completion(session, ...)` — insert record + content in one transaction.
- `list_chat_completion_metadata(session, *, limit, after)` — metadata-only page, newest first,
  cursor = `external_id` of the last item; returns items plus `has_more`.
- `get_chat_completion_summary(session)` — count, error count, token sums, average durations.
- `list_models(session)` — all served models.
- `get_model(session, external_id)` — one model or `None` (request validation).

## Migration

One Alembic revision (autogenerated, then reviewed): the three tables (incl. the seeded `models` row via `op.bulk_insert`), the status enum as a string
column with a CHECK-free `StrEnum`-backed type, and the composite `(created_at DESC, id DESC)` index.
